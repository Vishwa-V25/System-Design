# 🚀 System Design

This repository contains my notes, examples, and implementations of **Low-Level Design (LLD)** and **High-Level Design (HLD)** concepts. It serves as a learning resource for software engineering interviews and real-world system architecture.

## 📖 What is System Design?

System Design is the process of designing the architecture, components, modules, interfaces, and data flow of a software system to meet functional and non-functional requirements.

It helps transform a problem statement into a scalable, maintainable, and efficient software solution.

---

## 🎯 Why is System Design Used?

- Design scalable and reliable applications.
- Handle millions of users and large amounts of data.
- Improve maintainability and code quality.
- Ensure performance, security, and availability.
- Break complex systems into manageable components.

---

## 💡 Example

Suppose you are building an **Online Food Delivery App**.

- **HLD** decides:
  - Services (User, Restaurant, Order, Payment)
  - Database choice
  - Communication between services
  - Overall architecture

- **LLD** decides:
  - Classes like `User`, `Order`, `Restaurant`
  - Methods and relationships
  - Design patterns
  - Database models and object interactions

## 🏗️ High-Level Design (HLD)

High-Level Design focuses on the **overall architecture** of the system.

It defines:
- System components/services
- APIs
- Database selection
- Scalability
- Load balancing
- Caching
- Communication between services

**Goal:** Design how the entire system works.

---

## ⚙️ Low-Level Design (LLD)

Low-Level Design focuses on the **internal implementation** of individual modules.

It includes:
- Classes & Objects
- Relationships
- Design Patterns
- SOLID Principles
- Algorithms
- Database entities

**Goal:** Design how each component is implemented.

---

## 🔥 HLD vs LLD

| High-Level Design (HLD) | Low-Level Design (LLD) |
|--------------------------|------------------------|
| Overall system architecture | Internal class design |
| Focuses on scalability | Focuses on implementation |
| Components & services | Classes & objects |
| APIs & databases | Methods & relationships |
| Used by architects | Used by developers |
